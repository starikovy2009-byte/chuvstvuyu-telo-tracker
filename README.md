# ЧУВСТВУЮ ТЕЛО — трекер клуба

Статический адаптивный сайт на обычных HTML, CSS и JavaScript. Сборщик, React и Next.js не используются.

## Что подключено на первом этапе

- единый вход по email и паролю через Supabase;
- самостоятельная регистрация участника с именем, email и паролем;
- подтверждение email перед первым входом;
- восстановление забытого пароля;
- автоматическое определение роли и статуса по таблицам `profiles` и `memberships`;
- защищённое открытие режима тренера только для `role = coach` и `status = active`;
- открытие личного кабинета участника только для `role = participant` и `status = active`;
- отдельные экраны для статусов `pending` и `removed`;
- безопасный выход из аккаунта.

Кнопки выбора чужого профиля, прямой демонстрационный вход тренера и локальный пароль тренера удалены. Роль нельзя выбрать на странице или подменить через адрес сайта: она читается из Supabase после входа.

## Запуск через Visual Studio Code

1. Откройте в Visual Studio Code папку `C:\MyProjectsVS\Club`.
2. Установите расширение **Live Server**, если оно ещё не установлено.
3. Откройте `index.html`.
4. Нажмите правой кнопкой по `index.html` и выберите **Open with Live Server**.
5. Откроется адрес `http://127.0.0.1:5500/index.html` или близкий к нему.

Не открывайте `index.html` двойным щелчком. Для ES-модулей и входа через Supabase нужен локальный сервер.

## Как проверить временного тренера

1. Убедитесь, что интернет подключён.
2. В Supabase откройте **Authentication → Users** и убедитесь, что временный аккаунт тренера существует.
3. В таблице `memberships` у этого пользователя должны стоять `role = coach` и `status = active`. Это уже было настроено отдельно в SQL Editor.
4. Запустите сайт через Live Server.
5. На первой странице нажмите **«Войти в клуб»**.
6. Введите email и пароль временного тренера. Пароль храните только у себя; в файлы проекта его добавлять не нужно.
7. Нажмите **«Войти»**.
8. Сайт должен сразу открыть режим тренера со стартовым разделом **«Участники»**. Кнопки самостоятельного выбора режима тренера больше нет.
9. Нажмите **«Выйти из режима тренера»**. После выхода снова должна появиться приветственная страница.
10. Для дополнительной проверки обновите страницу после входа: в пределах этой вкладки браузера сеанс должен восстановиться. После закрытия вкладки сеанс заканчивается, потому что он хранится в `sessionStorage`, а не в `localStorage`.

Если появится сообщение о сети, сначала проверьте интернет и обновите страницу. Если открылся экран ожидания или блокировки, проверьте значение `status` в `memberships`.

## Как проверить регистрацию участника

1. На приветственной странице нажмите **«Создать аккаунт»**.
2. Введите имя, настоящий email и пароль длиной не меньше 10 символов.
3. После отправки сайт должен попросить подтвердить email.
4. Откройте письмо Supabase и перейдите по ссылке подтверждения.
5. Вернитесь на сайт и войдите с теми же email и паролем.
6. Новый участник со статусом `pending` увидит сообщение **«Заявка ожидает подтверждения тренера»**.
7. Когда запись в `memberships` получит `status = active`, повторный вход откроет режим участника.

## Восстановление пароля

На форме входа нажмите **«Забыли пароль?»**, введите email и откройте ссылку из письма. После задания нового пароля сайт вернёт пользователя к форме входа.

Для Live Server в Supabase уже разрешены локальные адреса:

- `http://127.0.0.1:5500/**`
- `http://localhost:5500/**`

После публикации на GitHub Pages нужно будет добавить публичный адрес сайта в **Authentication → URL Configuration**.

## Где находятся настройки Supabase

- `js/supabase-config.js` — Project URL, Publishable key и создание клиента Supabase;
- `js/auth.js` — вход, регистрация, восстановление пароля и чтение аккаунта;
- `js/app.js` — экраны и безопасная маршрутизация по роли и статусу.

В браузере используется только публичный Publishable key. В проект нельзя добавлять `secret`, `service_role`, пароль базы данных или пароль тренера.

Библиотека Supabase подключена как ES-модуль с зафиксированной версией `2.111.0` через jsDelivr. Поэтому для первого открытия сайта нужен интернет.

## Какие данные уже находятся в Supabase

Для авторизованных пользователей из Supabase загружаются и сохраняются:

- роли, статусы и заявки на вступление через `memberships`;
- имена участников через `profiles`;
- личные отметки, шаги и календарь через `daily_entries`;
- рейтинг, герои недели, звёзды месяца и результаты клуба;
- состав клуба, статистика и история участника в кабинете тренера.

Демонстрационные участники и записи из `localStorage` не используются в авторизованных режимах участника и тренера. Пароли, Supabase-сеанс и роль аккаунта в `localStorage` не сохраняются. Сеанс хранится только в `sessionStorage` текущей вкладки.

## Что пока остаётся локальным

- выбранные вкладки и временное состояние интерфейса;
- локальный предпросмотр имени и аватара в разделе профиля.

Следующим отдельным этапом остаётся загрузка аватаров и сохранение изменений профиля в bucket `avatars` и таблицу `profiles`.

## Структура проекта

- `index.html` — единая страница приложения и формы авторизации;
- `css/` — дизайн, адаптивность, компоненты и анимации;
- `js/supabase-config.js`, `js/auth.js` — Supabase и авторизация;
- `js/daily-entries.js`, `js/club-data.js`, `js/coach-data.js` — реальные отметки и данные клуба;
- `js/memberships.js` — заявки, удаление и восстановление участников;
- `supabase/` — применяемые вручную RLS-политики с инструкциями и откатом;
- `js/store.js` — локальное состояние интерфейса и совместимость со старой версией;
- `js/tracker.js`, `js/month.js`, `js/leaderboard.js`, `js/profile.js` — четыре вкладки участника;
- `js/admin.js` — кабинет тренера с реальными данными Supabase;
- `designs/approved/` — утверждённые макеты;
- `assets/source/` — исходные фотографии;
- `tests/manual-checklist.md` — технические и ручные проверки.
